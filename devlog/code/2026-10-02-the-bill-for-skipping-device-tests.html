Behind the code

The bill for moving the economy to the server without testing on a device

October 2, 2026 · written for other developers

Weekly build log from a solo dev (React Native, Expo, Zustand, Supabase). 58 commits this week, about 4,100 insertions and 1,500 deletions across 170 files. Last week I moved the whole economy server side without running it on a device. This week was the bill for that, and a few things in it are worth passing on.

"Doesn't touch money" is not a safe reason to leave something client side. When I made the economy server authoritative, I left chopping a tree on the client because it does not move cash or coins. The server's plot occupancy check correctly trusted only its own copy, so a chopped tree still existed server side and replanting failed with a generic error. The fix was a real endpoint. Then the fix caused a regression. My offline validation job had self healing logic that regranted a free starter tree whenever it saw an empty tree list, which was only ever true for an unseeded row until chop became real. Players chopped their only tree, reopened the app, and got a free one back. Any client only action that changes state the server validates against is not really client only.

A PL/pgSQL gotcha that blocked every equipment purchase. I read a row with EXECUTE format(...) INTO and then checked IF NOT FOUND. EXECUTE does not set FOUND, so the check always fired and no one could ever buy equipment. A sibling function had the same shape but was masked by an earlier static SELECT INTO. I wrote a regression check, but could not run the test harness locally because the Postgres test package has no Windows build, so that one shipped verified by reading and by manual testing only. I do not love that.

Device clocks versus server timestamps. I skipped a 46 minute batch and the timer sat on "1 min left" for over four minutes. The server stamps completion with now(), but the client compared it to the phone's Date.now(), and a phone about a minute slow left a minute on the clock after the server had cleared it. The fix is a small clock offset module fed by the Date header of every Supabase response, using the request midpoint to cancel latency, and replacing Date.now() everywhere a server timestamp is compared.

Migrations that adopt old data need to seed everything. Honeycrisp unlocks on the 11th harvest, using a server side counter. Existing players never unlocked it because my adoption migration never seeded that counter, so it started at zero. Tracing it took a diagnostic build and two failed guesses before I found the real cause. Lesson: when a new gate depends on a column, check every path that creates the row.

Closing a dialog is a decision too. The close X and tap outside on a weather pop up mapped to the cancel styled button, which for a bad event was Accept. Merely dismissing it took the full penalty. I added a dismissLeavesOpen option to my alert queue so dismissal presses nothing. I only caught it by driving an emulator and forcing events, which unit checks would never have found.

Smaller things. I made the OTA updates module load lazily inside a try/catch, since older dev builds without the native module crashed on startup with a red screen. The Tier 2 gate and ad skip durations moved into a config table I can tune without redeploying. I split one shared skip constant into two columns so raising one does not silently change the other. About a dozen fixes came out of structured emulator passes in one day, which is more than a week of code reading found.

The through line this week: the bugs were not in the hard parts. They were in the seams, the places where one system trusted another's assumptions. Running the real thing on a device found far more than reviewing it did.
