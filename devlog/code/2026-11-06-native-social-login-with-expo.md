# What I learned shipping native social login with Expo, and a scroll bug that was my own touch handler

Solo dev, React Native with Expo and Supabase. The game is live on both stores, and this week was a small one in commit count, about 10 commits, but a few of them taught me something.

**Native sign in forces a store build, so version your runtime on purpose.** I added Sign in with Apple and Google through signInWithIdToken in Supabase. Both libraries are native modules, so they cannot ship over the air. The final commit this week was tiny: paste in the real Google client IDs, add the reversed iOS client ID as the URL scheme in app.json, and bump version and runtimeVersion to 1.1.0. The bump matters. With expo-updates, runtimeVersion decides which installed builds an update can reach. Once I moved to 1.1.0, an update published from main reaches only 1.1.0 builds, so anyone still on 1.0.x is cut off from it. I wrote down the last commit those players received so that any urgent fix for them can be published from a branch made off that commit. If you do not decide this deliberately before a native bump, you find out when a bug fix does not arrive.

**The Google side was more config than code.** The code was a few dozen lines. The work was a Google Cloud project, an OAuth consent screen, a Web client ID and an iOS client ID, publishing the consent screen, and enabling the provider in Supabase. One gotcha cost me time: in the Supabase Google provider page, saving the client IDs does nothing unless the Enable toggle at the top is on. Another: the "100 user cap" on the consent screen only counts sensitive or restricted scopes. I only ask for name and email, so it does not limit me. I dropped the logo from the consent screen, which avoids needing brand verification. App Store rule 4.8 means iOS shows both buttons or neither.

**A scroll bug that was my own touch handler.** On my iPhone, the market price list would not scroll. The list sat inside two nested Pressables, with the outer one meant to catch taps outside the sheet and close it. The rows themselves have nothing touchable, so the swipe landed on the Pressable and got treated as a press. I could not reproduce it on the emulator, so the fix is a likely cause, not a proven one. The tap outside catcher is now a sibling behind the sheet instead of a parent around it. I applied it to four modals that shared the pattern and added a visible scrollbar. I will not call it confirmed until more people on iOS use it.

**Ad failures that were really network policy.** One player had four no fills on work WiFi and none at home. AdMob reports a blocked network as a no fill or a timeout. I also found that my timeout handler matched the string "timed out", but the SDK error says "timeout occurred", so those fell through to a generic message. Both cases now tell the player to try mobile data. Small thing, but a generic error teaches nobody anything.

**A pricing change I cannot judge yet.** I lowered the ad price of four boosts from the first week's data. Those actions made up 53 of 151 ads in the sample, so if players do not use them more, total ads could fall by roughly 24 percent. I made the change in a config table, so I can revert it without a release. The sample is tiny, so I am treating this as a one week experiment, not a conclusion.

**Reading my own funnel.** App Store search brought 623 of 654 impressions in the first stretch, but only 16 of those opened the listing, about 2.6 percent. Nine first time downloads, mostly people I know. So the leak is before the listing, and I am iterating on the icon and first screenshot, not the game. Numbers this small are directional at best.

**A process fix.** The top priorities file had gone five weeks stale and I had called the docs fine after a keyword search. I tightened the rules for my AI coding agent: read the affected sections, fix stale text on sight, and check claims against full sources. A search for a word is not a review.

Happy to answer questions about any of it.
