# Real navigation, a referral system and breaking up one giant screen file

Weekly build log from a solo dev building a mobile business sim (React Native/Expo, Zustand, Supabase). Big week, arguably the biggest single push since the project started: real navigation, a chunk of new economy content, a referral system with server-side attribution, and a fix for a bug class I'd been putting off.

The structural piece first, since everything else builds on it: for months every screen has lived inside one giant `OrchardDebugScreen.tsx` file, growing by copy-paste every time a new system shipped. This week that started unwinding for real. Added a bottom tab navigator and cut the Orchard domain, plots, watering, harvesting, weather display and buildings, orchard-wide boosts, out into its own real screen, pulling from the same store slices rather than duplicating logic. Processing and Market are still debug-screen-only for now; this is a three-part migration and Orchard was part one. The genuinely debug-only stuff (force season, force pest event, grant apples, reset save) stayed behind a `[DEV]` gate reachable from Account, confirmed to not render at all in a `__DEV__`-false build. One side effect worth flagging for anyone doing a similar split: alert dialogs from two different screens can now fire close together if both are active, so I added a shared alert queue rather than letting two `Alert.alert()` calls race each other and silently drop one.

Content-wise: two more orchard plots (a 3rd and 4th, cash-gated with the same construction-timer mechanic the weather buildings already used, versus the always-instant 2nd plot), two permanent maintenance upgrades (drip irrigation, compost system, the latter gated behind the former), a second concurrent processing queue slot, and grade-exclusion toggles so you can tell the processing system to stop pulling from your Grade C stock. The bigger structural change buried in that list: every equipment upgrade past your first-ever purchase now goes through the same construction-timer system the weather-mitigation buildings pioneered a few weeks back, rather than resolving instantly. Generalizing that timer system to a second domain was mostly just confirming the existing skip-with-coins logic didn't have any weather-specific assumptions baked in, it didn't, so this was more wiring than new logic.

I also did an audit pass on the 13 scripted engagement beats from the GDD and found 5 of them still flagged `mechanicImplemented: false` even though the systems they reference (weather, recipes, the Tier 2 gate) had shipped weeks earlier. Stale flags, not stale features, but stale flags are exactly the kind of thing that quietly rots a save-flow test. Fixed the flags and gave harvest 8 an actual coin grant instead of narration-only, since a "reward" beat with a fake reward is arguably worse than no beat at all.

The referral system is the piece with the most moving parts: a unique code and shareable deep link per player (`https://www.foundersplot.com/refer/CODE`, Universal Links, reusing the AASA/associatedDomains infra I stood up for the password-reset flow a couple days ago), a Supabase migration adding 4 tables (`referral_codes`, `referral_redemptions`, `referral_config`, `pending_coin_grants`), and two Edge Functions (`referral-reward`, `claim-pending-grants`) that keep JWT verification on by default rather than the open-webhook pattern the AdMob/RevenueCat functions use. Rewards are a claim-based pull rather than a push, both sides tap "Claim Pending Rewards" rather than the server trying to push coins into a client that might be offline, which sidesteps a whole class of "player was offline when the reward fired" bugs. Config (reward amounts, monthly cap) lives in a single database row the Edge Function reads live, so tuning it later doesn't need a redeploy. Built the Founding Farmer badge alongside it, first 500 accounts ever, awarded via a Postgres trigger on `auth.users` rather than any client-side logic, which means it's tamper-proof by construction but also means the read policy currently only lets a player see their own row, a leaderboard or co-op display (both named in the GDD) would need that policy widened later.

Also shipped, smaller: the password reset flow that was actually the trigger for building Universal Links infra in the first place, and a native App Store/Play Store rating prompt (`expo-store-review`) gated behind a 60-day cooldown and 3-lifetime cap on our own side, stacked on top of whatever quota each platform enforces internally.

Net effect: a lot of surface area, and I mean that as a caution, not a boast, everything in this log is described as "built" against the design doc and the test suite, with zero on-device passes so far. Last week's whole post was about the gap between typechecks-clean and actually-works-in-your-hand, and this week has roughly ten times the surface area that week did: new nav, new purchases, new timers, and a two-device server-attribution flow that can't really be verified any other way. Next week is entirely testing, working the checklist top to bottom, before any new feature work starts.
