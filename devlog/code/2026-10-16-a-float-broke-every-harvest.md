# A float that broke every harvest on fresh accounts

Weekly build log from a solo dev (React Native, Expo, Zustand, Supabase). 35 commits this week, roughly 97 files touched, six new Postgres migrations (0070 through 0075). Mostly bug fixes and wording, but three of them taught me something worth passing on.

**A float broke every harvest on fresh accounts.** I had switched the app's local timestamps to a server synced clock. That clock includes an offset, so it can return fractional milliseconds. A reset account re-seeded a stamp like 1791694773561.5, and a Postgres function doing `(... ->> 'lastWateredAtMs')::bigint` threw on it. The Edge Function returned 500 and the app showed "Not ready yet," which was the wrong message, so I did not see the real problem for a while. Fixes: the clock now returns whole milliseconds, the SQL rounds before casting, a migration cleans up stored fractional values for existing players, and the app shows "Could not harvest" with the real reason for server failures. Lesson: a catch all error message hides bugs from you as well as from players. I also could not run my SQL harness for this one and verified on the live account, which I still do not like.

**Two clocks means two answers.** The market weekend was computed in UTC on the server and in the phone's local zone in the app. For a Kansas player they disagreed from 7 pm to midnight every Friday and Sunday. I replaced both with one US Central calculation with daylight saving rules written out by hand, so there is no dependency on Intl time zone support, which is patchy on Hermes. I tested Friday and Sunday evenings, both DST weekends (47 and 49 hour weekends), New Year, and identical output under UTC, Los Angeles, and Tokyo machine zones. The app also stopped trusting the phone clock for market logic entirely.

**Stacking multipliers was the wrong model.** A second 2x purchase was either refused or became 4x. I changed it to a counted boost: one per purchase, one consumed per harvest or batch. It took two small columns and two migrations, and a conversion step that turns old stored 2x multipliers into counts. Counts are easier to display and impossible to misread.

**Process fixes.** I wrote a read only script (`npm run check-deploys`) that compares each Edge Function's last commit, including the shared files it imports, against its deploy time from the Supabase CLI. Its first run flagged two functions I had committed but never deployed. I also deleted 38 stale scratch scripts that no longer compiled and excluded the Deno folder from tsconfig, so `tsc` is clean for the whole project.

**UI sequencing.** A popup queue got a hold mechanism so a sale result can jump ahead of other alerts, and a full screen card keeps the queue held until it is closed. Before that, popups stacked in a confusing order.

**Misses.** Apple's earlier review rejected a build for showing a raw AdMob no fill error. It took nine call sites and one shared helper to fix, which I should have written the first time. Still open: a second device shows stale coins after a claim elsewhere, and a stale ad button plays a full ad before refusing.
